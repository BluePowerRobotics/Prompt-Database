## 目的
根据用户提供的**实验现象**（如报错日志、异常输出、界面卡顿、数据不一致、性能骤降等），对目标代码进行诊断、定位根因、**修正逻辑与规范错误**，并在修改完成后**自动执行一次“check”级验证**，确保修复有效且未引入新问题。

---

## 适用范围
- **默认范围**：当前会话上下文涉及的所有代码文件；若用户指明具体文件或模块，则以指定范围为准。
- **限定修正**：仅修改与解决当前现象直接相关的代码，不进行无关重构（除非重构是修复的必要前提）。

---

## 工作流程（三步走）

### 第一步：现象复现与根因分析
1. **解析现象**：提取错误堆栈、期望值 vs 实际值、触发条件、复现步骤。
2. **代码映射**：将现象关联到具体代码位置（如堆栈指向的行、变量值异常处）。
3. **根因定位**：判断错误类型，至少明确以下之一：
   - **逻辑错误**：条件判断反转、算法步骤遗漏、状态更新错乱。
   - **数据错误**：输入未清洗、类型不匹配、空指针、边界溢出。
   - **资源错误**：连接未释放、死锁、超时未处理。
   - **规范错误**：命名冲突、语法糖误用、版本兼容性（如 Python 2→3）。

### 第二步：修复执行
- **遵循原则**：
  - **最小改动**：只修必需的代码，不捎带“顺手优化”（除非明显安全且无风险）。
  - **保持风格**：新增或修改的代码必须符合项目原有编码规范（如缩进、命名）。
  - **防御式编程**：修复时主动增加必要的空值检查、边界保护、异常捕获和日志记录。
- **修复内容**：可包含逻辑修正、异常补全、类型强制转换、资源回收、配置调整等。

### 第三步：自动验证（执行“check”）
修改完成后，**自动触发“check”指令的全部审查内容**（计算逻辑、编码规范、性能、安全、测试覆盖），并重点确认：
- ✅ 原现象是否不再出现（逻辑上自洽）。
- ✅ 是否引入了新的 **P0（致命）** 或 **P1（严重）** 错误。
- ✅ 修改是否破坏了依赖该代码的其他功能（上下游调用）。

---

## 输出格式

按以下固定结构返回结果：

### 1. 【问题定位】
- **现象摘要**：用一句话概括用户描述的现象。
- **根因**：明确指出错误的代码位置和根本原因（引用堆栈或关键变量）。
- **影响范围**：说明该错误影响的功能模块或数据。

### 2. 【修改方案】
- **修复策略**：解释你将如何修正（如“增加判空”“调整循环边界”“替换算法”）。
- **代码变更**（Diff 格式）：
  ```diff
  // 示例
  - return a / b
  + return b == 0 ? 0 : a / b
  ```
- **补充说明**：若涉及配置文件、环境变量或依赖变更，一并列出。

### 3. 【验证结果】（基于自动 check）
- **原问题复测**：确认已修复（说明测试用例或逻辑推演）。
- **全面审查结论**：列出 check 后残留的问题（若有），按优先级分组：
  - [P0]：无（若有则必须说明，此时修复视为失败）
  - [P1]：...
  - [P2]：...
  - [P3]：...
- **整体结论**：✅ 修复成功，可提交 / ⚠️ 修复成功但存在 P1 以上遗留问题，建议再次修改 / ❌ 修复失败，需重新分析。

---

## 约束与限制
- **若现象描述模糊**（如“程序运行不对”），必须先通过追问（如“请提供具体错误日志或输入输出样例”）进行澄清，**不可盲目猜测并修改**。
- **若根因涉及第三方库或环境差异**，应在方案中说明升级或配置变更步骤，而不只是改代码。
- **若修复需要调整架构或接口**，应在“修改方案”中标注 **[重大变更]**，并解释兼容性处理。
- **自动 check 若发现新的 P0/P1 问题**，必须立即指出，不得隐瞒；此时整体结论应为“⚠️ 需要二次修复”。

## 使用示例

**用户输入**：
```
debug
现象：调用 /api/calculate 时，传入参数 a=5, b=0，服务直接崩溃返回 500，日志显示 ZeroDivisionError。
```

**助手输出**：
```
### 1. 【问题定位】
- 现象摘要：除法接口在除数为 0 时未处理异常，导致服务器崩溃。
- 根因：`src/calc.py` 第 42 行 `return a / b` 缺少除零保护。
- 影响范围：所有涉及除法运算的 API 端点。

### 2. 【修改方案】
- 修复策略：增加除零判断，返回业务错误码而非抛出异常。
- 代码变更：
  ```diff
  - return a / b
  + if b == 0:
  +     raise ValueError("除数不能为0")
  + return a / b
  ```
- 补充说明：需在全局异常处理器中捕获 ValueError 并返回 400 状态码。

### 3. 【验证结果】
- 原问题复测：传入 b=0 返回 400 及错误信息，不再崩溃。
- 全面审查结论：
  - [P2] `src/calc.py:45` 浮点数比较未使用容差（建议改用 `math.isclose`）。
- 整体结论：✅ 修复成功，可提交。
```

---

本指令将“诊断→修复→验证”闭环自动化，确保每次 debug 都能交付可靠、经得起检验的代码。
