## 改进措施（9/3 实施）

### 对场景 3 的诊断

远处视觉误差远大于 MT1 输出的 `stdDev`，而旧实现存在两个缺陷：

1. **R 上界截断**：`mapStdToR` 在 `STD_HIGH` 处把 R 截断在 `0.01 × R_MAX_SCALE`，因此距离再远、stdDev 再大，视觉观测噪声也不会继续增长，滤波器仍然过度信任远处的视觉解。
2. **无离群点拒绝**：失真的视觉解直接被当作有效观测更新，单个误观测即可把位姿带偏。

### 具体改进（AdaptiveEKF/UKF）

1. **去除 R 上界**：`mapStdToR` 改为无上界线性映射，`std > STD_HIGH` 后继续线性放大，不再封顶。
2. **距离二次缩放**：位置方向的 R 额外乘以 `distFactor = (dist / DIST_REF_M)²`（`dist > DIST_REF_M` 时），体现视觉位置误差随距离近似二次增长。
3. **标签数缩放**：位置方向的 R 额外乘以 `tagFactor = TAG_REF / tags`（标签 `< TAG_REF` 时，上限 `TAG_SCALE_MAX`），标签越少解算越不可靠。
4. **马氏距离门控**：视觉更新前先 `gateVision()` 计算 `d² = innovᵀ·S⁻¹·innov`，仅当 `d² ≤ GATE_THRESHOLD²` 才接受本次更新，其余作废（predict 照常，依赖里程计直到下一次可信观测）。

详见 [Theory.md](./Theory.md) §5.3–5.5、[Theory5D.md](./Theory5D.md) §6.4、[Params.md](./Params.md) 顶部「视觉 R 自适应与马氏门控」。

### 待验证

- 远离 tag 时位姿应不再被视觉带偏，视觉恢复后仅做缓慢修正。
- 场景 1（MT1 偶尔无数据）暂未改动，需进一步区分是遮挡、曝光还是算力/帧率问题。

# 9/10

在 into the deep 不完整场地测试 Fusion5D\_D2TestOpmode（D2 模式 5D 融合）

## 腾空实验

将机器人腾空（车轮离地）时：

- **AdaptiveEKF(D2) 停止更新**——位姿基本不再变化，腾空期间无有效运动/观测信息；
- **5D 定位器（EKF5D / UKF5D）均持续更新**——加速度计控制输入仍在驱动预测，但**误差较大**：腾空段缺少外部观测校正，纯惯导二次积分快速漂移。

## 正常行驶精度

未腾空、正常行驶时：

- **5D 定位器持续漂移**；
- **AEKF 误差远低于 5D 定位器**——两者视觉/里程计输入相同，唯一差异是 5D 额外交入了加速度计控制输入。

## 同类对比

与 9/3 结论一致：**EKF5D 与 UKF5D 未观察到明显性能差异**。

## 加速度计实测（AccelTest + Pinpoint）

| 项目                   | 实测值                      |
| -------------------- | ------------------------ |
| BNO055(ExpImu) 读数刷新率 | ≈ **0.7 s / 次（≈1.4 Hz）** |
| 读数噪声范围               | ±1 in/s²                 |
| 底盘最大速度               | ≈70 in/s                 |
| 静止起步最大加速度            | ≈140 in/s²               |
| 最大减速度                | ≈−200 in/s²              |

## 修正诊断：更新率（延迟）主导，而非噪声

- 加速到满速 ≈ `70/140 = 0.5 s`，满速刹停 ≈ `70/200 = 0.35 s`，**均短于一个采样周期 0.7 s** →
  加速度计在一次机动内近乎只给出一个“保持值”，属**欠采样 + 零阶保持滞后**；而 `predict()`
  以 50 Hz 每帧都用该保持值乘 `dt` 积分，滞后误差被反复注入。
- 量级估算：速度偏差 ≈ `a_err·dt / K`（`K` 为里程计对速度的修正增益）。取
  `a_err = 140 in/s²`、`dt = 0.02 s`、`K ≈ 0.09` → 稳态速度偏差 ≈ **30 in/s**（≈45% 最大速度）；
  减速段若仍报 +140（真值 −200）则 `a_err ≈ 340`，偏差可达 **\~70 in/s**。
  纯零阶保持上界：`½aτ² = ½×140×0.7² ≈ 34 in`、`Δv = aτ ≈ 98 in/s`。
- **噪声项可忽略**：σ=1 in/s² 时 5 s 位置随机游走 std ≈ 0.65 in，远小于上述系统误差。
- 因此原「噪声偏大」推测修正为：**更新率过低（≈1.4 Hz）导致 0.7 s 级系统延迟**。

### 根因确认：驱动轮询间隔（已实测验证）

[ExpImu.java](../Accelerometer/ExpImu.java) 初始化调用
`imu.startAccelerationIntegration(new Position(), new Velocity(), 1000)`，其中 `1000` 为
**驱动轮询间隔(ms)**，与实测 \~1 s 刷新率高度吻合（BNO055 NDOF 本身的输出率远高于此）。
已改为 Dashboard 可调 `ExpImu.INTEGRATION_POLL_MS`。

**实测对照（AccelTest）**：

| `INTEGRATION_POLL_MS` | 实测刷新率            | 滞后       | `∫a·dt` vs Pinpoint 速度 |
| --------------------- | ---------------- | -------- | ---------------------- |
| 1000（原值）              | ≈1.4 Hz（0.7 s/次） | 0.7 s 级  | 明显滞后 / 偏差              |
| **15**                | **≈35 帧/s**      | **基本消除** | **波形基本吻合**             |

- 15 ms 时刷新率升到 ≈35 Hz 后不再上升，瓶颈已转移到**读取整个 BNO055 寄存器组的 I2C 耗时**，
  继续调小该参数不会再有提升。
- 结论：0.7 s 刷新率的根因确为 `msPollInterval = 1000`，**并非 BNO055 带宽不足**，属纯软件配置
  问题，更新率可由该参数解决。

## 加速度计静态零偏（实测）

- 静止时 ax / ay 存在 **1\~5 in/s² 的稳定偏置**，读数在该值附近小幅震荡；
- **移动后再静止，偏置值会改变，但静止期间保持不变**。

**原因**：NDOF 输出的线性加速度为 `a_lin = a_meas − g_est`（实测加速度 − 融合估计的重力向量），
静置残差 = **重力方向估计误差 + 加速度计自身零偏**。水平偏置 1\~5 in/s² 对应姿态误差
`δ = asin(a/g)` ≈ **0.15°\~0.74°**（`g = 386.09 in/s²`），属消费级融合的正常量级。
注意 **yaw / 磁力计误差不会造成重力泄漏**，故问题在 roll / pitch 估计层面。

**为何运动后偏置改变、静止后不变**：运动期间姿态主要由陀螺积分主导，同时真实动态加速度污染了
加速度计的倾斜校正、内部零偏/校准状态被更新；停止后融合重新收敛到**新的**稳态误差，故静止期间
保持不变（若静止更久，仍可能缓慢重收敛）。

**影响**：

- 偏置是 DC 项，二次积分按 `½bt²` 增长：`b = 3 in/s²` → 5 s **37.5 in**、10 s **150 in**；
  且每次机动后偏置方向/大小改变 → 与「5D 持续且不规则漂移」一致；
- 静止 `|a|` 为 1\~5 in/s²，远高于 ZUPT 门限 `0.5 in/s²` → **零速检测永不触发**。

# 9/11（完成校准后复测）

先用 `AccelCalibration` 完成 BNO055 手动校准（四项达到 `s3 g3 a3 m3`），随后重跑
[AccelTest.java](../../opmodes/AccelTest.java#L297-L303) 复测加速度计误差。

## 观测：误差仍随位姿变化，且同一位姿随时间变化

按「误差是否来自重力」的判据——若误差仅来自重力方向估计残差 δ（世界系固定），则：

| 应不变的量                        | 含义         |
| ---------------------------- | ---------- |
| `err_world = R(θ)·err_body`  | 与航向无关，恒定   |
| `\|err\|`（= `\|err_world\|`） | 与任何姿态无关，恒定 |
| `err_z`                      | 与航向无关      |

实测结果（AccelTest 第 297–303 行所在的「重力误差不变量」段）：

- `err_world` 的 x / y 分量**仍随车辆位姿变化**，未表现出应有的“恒定”；
- **同一位姿、不同时间**测得的误差也不相同。

⇒ 两项判据同时被否定，说明**误差不止来自重力**。

## 判断：磁场干扰

与重力型误差（世界系常量、模长恒定）对比，实测误差中还含有**体坐标固定、且随时间漂移**的成分。
查阅资料后判断主要来源是**周围线路的磁场干扰**：

- NDOF 融合依赖磁力计解算航向/姿态，电机、电调、电池大电流线缆都会在板级产生变化磁场；
- 磁场环境变化 → 磁力计标定（含刚保存的 MAG 校准）失效 → 融合姿态与线性加速度基准随之改变；
- 这也解释了「同一位姿、不同时间结果不同」——扰动源是电流引起的磁环境，而非几何量。

## 决策：放弃使用 BNO055

赛场上电机、电调与大电流线缆无法移除，走线路由又随结构固定，**不可能消除磁场干扰**；
校准文件只能固化某一时刻的磁环境，无法覆盖运行中变化的磁场。5D 定位器赖以工作的加速度输入噪声并非无偏，**故放弃 BNO055 作为 5D 的加速度源**。

## 5D 定位器验证结论

- **可行性验证成功**：EKF5D / UKF5D（D2、D3 接入）代码链路完整，`predict` 与 Pinpoint / 视觉观测的

- **性能未达预期**：受上述硬件限制（加速度计读数不可信），**并未观察到 5D 定位器优于 3D 定位器**。
